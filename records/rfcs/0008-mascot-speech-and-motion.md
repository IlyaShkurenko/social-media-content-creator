# RFC-0008: Mascot speech line and independent local motion

- Status: Accepted
- Date: 2026-08-18
- Decision owners: Project maintainers and product owner
- Decision type: Storyboard/concept schema extension, CTA layout, renderer motion

## Summary

Give the CTA's mascot a per-concept spoken line and a pose choice, and animate
it independently of the rest of the end card (pop-in, then an idle pulse)
instead of the single uniform Ken-Burns zoom every static card currently
gets. Both are additive and optional: a storyboard without `mascot_line` set
renders exactly as before.

## Context

`evals/assets/brand/brand-kit.json`'s `usage_contract.mascot` already permits
this, unlike product UI: "Animation may change pose or expression but must
preserve the pin silhouette, yellow palette, face, and recognizability." Two
approved static variants already exist — `tict-mascot-1.png` (arms straight
out, neutral) and `tict-mascot-2.png` (arms raised, excited/waving) — same
face on both. Mascot animation has been an explicitly tracked, unimplemented
gap since the pipeline's early specs ("Mascot animation... remain absent").
Today the CTA is one flattened PNG (logo + mascot + headline + button baked
into a single image) that then gets one uniform zoom for its whole duration —
there is no way to move the mascot differently from its background.

## Decision

### 1. The mascot's line and pose are planner output, same pattern as VOICE-1.1

`AdvertisingConcept` gains `mascot_line: str` (a short line in the mascot's
voice, thematically tied to that concept's hypothesis — not generic
boilerplate) and `mascot_pose: Literal["neutral", "excited"]`, generated by
the same Gemini call that already produces `hook_voice_delivery`.
`compile_concept_storyboards` copies both onto the compiled CTA scene
(`StoryboardScene.mascot_line` / `.mascot_pose`) and swaps that scene's
`hero` brand-asset overlay to the matching mascot file — the only CTA content
this touches; the existing four locked elements (logo, headline, action
copy, and their `layout_intent`) are unchanged, preserving BRAND-1.1's exact
product/CTA guarantee for everything except this one new addition.
`mascot_line` is capped at 45 characters — short enough to read aloud
comfortably inside the CTA's ~4-second duration.

### 1a. The mascot's line is spoken, not just displayed

`_compile_cta_scene` also overrides the compiled CTA scene's `voiceover`
with `concept.mascot_line`, replacing the template's generic tagline
narration ("Plan less. Travel more with tict.") with the mascot's own line.
This needed no new narration code: `generate_scene_narration` already
synthesizes every scene from its own `voiceover` field, so the existing
per-scene TTS, duration-fitting, and `.srt` sidecar generation pick it up
unchanged. The CTA's burned-in bottom subtitle overlay is unconditionally
suppressed for `purpose == "cta"` regardless of voiceover content, so this
cannot duplicate the line as a second on-screen caption — it appears once,
in the speech bubble, spoken aloud at the same moment the card begins.
`onscreen_text` and `call_to_action` — the visible headline and button copy
— are untouched, so BRAND-1.1 fidelity for what's *drawn* is unaffected;
only what's *spoken* for this one scene changes per concept.

### 2. A fifth, optional CTA layout element

`CtaLayout`/`_PreparedCtaLayout` gain an optional `mascot_line` box occupying
the previously-unused `upper` region (between the existing `top` logo and
`center` hero) — the natural speech-bubble position above the mascot's head.
It only participates in `_prepare_cta_layout`'s explicit-`layout_intent`
branch and its safe-area/overlap validation; the legacy auto-flow fallback
branch is untouched, because every storyboard that sets `mascot_line` is
freshly compiled by `compile_concept_storyboards`, which always emits an
explicit `layout_intent` entry for it. A storyboard without `mascot_line`
renders through the exact original four-element path.

### 3. The mascot moves independently via a pre-rendered frame sequence, not an ffmpeg time expression

Rather than a live per-frame ffmpeg filter expression (fragile to write and
to test), the CTA's frames are pre-composited in Pillow — the same tool the
rest of this renderer already does all pixel-level work in — one static
background (logo, headline, button, everything except the mascot) reused
across every frame, with the mascot pasted at a scale computed by a pure,
directly unit-testable function of elapsed time: a two-segment pop-in
overshoot-then-settle (0 → 115% → 100% over the first ~0.4s) followed by a
slow sinusoidal idle pulse (±2.5% amplitude) for the remainder of the CTA's
duration. The frame sequence is then encoded once via `ffmpeg -framerate`,
replacing the flat-PNG-plus-uniform-zoom path only when `mascot_line` is
set; every other scene (hook, product_demo) and every CTA without a mascot
line keep today's exact rendering path unchanged.

## Consequences

The mascot can now carry a concept-specific line — shown, and spoken as the
CTA's own narration — and visibly perform instead of sitting inertly inside
a zoomed still frame, without touching product-demo fidelity, the existing
four CTA elements, or any storyboard that doesn't opt in.

### Rejected: generative image-to-video and rig-style cutout animation

Two options for a fuller "mascot runs and acts for 15 seconds" performance
were raised and both declined for now, not implemented as a lesser version.
Generative image-to-video (e.g. Runway) was rejected because a flat,
minimal-detail vector mascot is a poor fit for models trained mostly on
photoreal/textured subjects — sustained motion risks drifting off the
approved silhouette, palette, and face the brand kit's usage contract still
requires, and trusting the result would need its own temporal-consistency
evaluator investment before any campaign could rely on it, exactly as
RUNWAY-2 already does for the hook. Reliable brand-consistent generative
animation would most likely need model fine-tuning, which was explicitly
declined as disproportionate. A local rig-style cutout animation (separate
approved arm/leg/expression layers, recomposited and moved by code) was also
considered, but the additional mascot artwork available is a set of distinct
whole-character illustrations, not interchangeable rig parts, so it cannot
support this technique as-is. Either path remains open in the future only
behind purpose-built, brand-consistency-appropriate assets or evaluation,
each meriting its own RFC.

Actual lip-synced speech also remains explicitly out of scope — this is
timed text-plus-motion, not generated mouth animation.
